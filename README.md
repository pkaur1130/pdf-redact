# pdf-redact

Removes text from a PDF. Does not draw a box over it and hope.

## The problem this exists for

Most tools that offer "redaction" draw a black rectangle on top of the words.
The words are still in the file. Select them, copy them, paste them somewhere —
there they are. Court filings and government releases have leaked the exact
thing they were redacting this way, more than once.

This edits the PDF's content stream. Text-showing operators whose glyphs fall
inside a redaction area have their strings emptied, which deletes the characters
while leaving the positioning of everything after them intact. A black box is
drawn too, but the box is cosmetic. The removal is the product.

## Where it errs

Toward removing too much. Glyph width is estimated rather than measured, because
measuring needs the embedded font's metrics and those are not always readable.
The estimate is deliberately generous, so the failure mode is a word removed
that did not need to be — never a word left behind that should have gone.

## Checking it yourself

Do not take the above on trust. `test/redact.test.ts` contains the only test
that really matters: redact a document, then read the text back out of the file
and assert the secret is absent. Two things have to be undone to do that — the
content streams are deflated, and pdf-lib writes glyphs as hex strings — so a
naive byte search comes back empty against a file that still holds every
character. That false pass is what the test is built to avoid.

```
npm install && npm test
```

## Where it comes from

Extracted from [EkaanHub](https://ekaanhub.com), where it powers
[Redact PDF](https://ekaanhub.com/redact-pdf). The rest of that codebase is not
public. This module is, because it is the part where a claim about your
documents deserves to be checkable rather than believed.

Generated by `scripts/extract-redact.mjs` from the module actually in
production, so it cannot drift from the code that runs on the site.
